## 用户反馈报告V4.3 — 编辑内容持久化（localStorage）
- 用户问题：分类调整、插入图片等编辑刷新后丢失
- 解决方案：localStorage 持久化，每次编辑自动保存，页面加载自动恢复
- 持久化内容：分类修改、备注文本、自定义标签、上传图片（base64）
- 每行通过反馈原文前80字符生成稳定 hash ID 作为 localStorage key
- STORAGE_PREFIX：emoji_ / wangzai_ 区分两份报告
- 编辑后自动调用 saveRowData() + flashSaveIndicator()（显示"✓ 已自动保存"2秒后消失）
- 页面加载时 loadAllEdits() 恢复所有编辑，并刷新分类筛选栏和标签筛选栏
- 新增工具栏按钮：📥导出编辑 / 📤导入编辑 / 🗑️重置所有编辑
- 导出为 JSON 文件，导入可恢复；重置会清空 localStorage 并刷新页面
- 图片存储：上传后通过 canvas.toDataURL 转为 base64 JPEG 存入 localStorage（视频太大无法持久化，刷新后需重新上传）
- QuotaExceededError 处理：自动移除媒体数据再重试保存

## 用户反馈报告V4.4 — 云端同步（GitHub API）
- 用户要求：编辑内容在云端也保存，不只是浏览器本地
- 方案：GitHub Contents API 读写仓库内 JSON 文件
- 云端存储路径：data/emoji_edits.json、data/wangzai_edits.json
- Token 配置：用户通过页面内 prompt 输入 GitHub Fine-grained PAT，存入 localStorage
- Token 权限：Contents → Read and Write，限定仓库 sogou-feedback-report
- 工作流：编辑后 3秒防抖 → collectAllEdits() 收集所有变更 → PUT 到 GitHub API
- 页面加载：先设 data-original（原始分类），再 loadAllEdits（恢复编辑），再 updateCloudUI
- 新增工具栏按钮：☁️ 同步到云端、📥 从云端恢复、🔑 配置 Token
- 状态指示：cloud-status 元素显示同步中/已同步/失败等状态
- 双重保障：localStorage 本地 + GitHub 云端，云端恢复时 cloud 覆盖 local
- 修复：Token 配置从浏览器 prompt() 改为自定义模态框（prompt 被 file:// 协议和某些浏览器策略屏蔽）
